Bloques **B07–B08**. Los fragmentos omiten los `import` y el manejo de excepciones. Salvo que se diga otra cosa, se usa `SAXParserFactory.newInstance()` sin activar espacios de nombres. Los XML se muestran indentados para leerlos mejor, pero el fichero no tiene espacios ni saltos de línea entre etiquetas salvo que el enunciado diga que la indentación es real.

<Quiz id="b3-01" title="Modelo push">
¿Qué describe mejor el funcionamiento de SAX?

- [ ] La aplicación pide el siguiente evento con `next()`.
  > Eso es StAX (modelo *pull*).
- [x] El parser recorre el documento una vez y llama a los métodos del manejador cuando encuentra cada parte (modelo *push*).
  > Correcta (B07.1).
- [ ] Construye un árbol en memoria y después lo recorre.
  > Eso es DOM.
- [ ] Permite volver atrás para releer un elemento anterior.
  > SAX no retiene el documento; hay que guardar estado propio o releer.
- [ ] Convierte el XML en objetos Java anotados.
  > Eso es JAXB.
- [ ] Solo funciona con documentos pequeños.
  > Precisamente es adecuado para documentos grandes.

Repasar: **B07.1, B02.1**.
</Quiz>

<Quiz id="b3-02" title="Arrancar el análisis">
¿Qué secuencia lanza correctamente el análisis con un manejador propio `MiHandler extends DefaultHandler`?

- [ ] `new SAXParser().parse(new File("a.xml"), new MiHandler());`
  > `SAXParser` es abstracta: se obtiene de la factoría.
- [ ] `SAXParserFactory.newInstance().parse(new File("a.xml"), new MiHandler());`
  > La factoría no parsea.
- [x] `SAXParserFactory.newInstance().newSAXParser().parse(new File("a.xml"), new MiHandler());`
  > Correcta (B07.1).
- [ ] `DocumentBuilderFactory.newInstance().newSAXParser().parse(...)`
  > Esa factoría es la de DOM.
- [ ] `new MiHandler().parse(new File("a.xml"));`
  > El manejador recibe eventos; no analiza.
- [ ] `SAXParserFactory.newInstance().newSAXParser().parse(new MiHandler(), new File("a.xml"));`
  > Primero va el origen y después el manejador.

Repasar: **B07.1**.
</Quiz>

<Quiz id="b3-03" title="Orden de los callbacks">
Para este XML, sin espacios entre etiquetas, ¿en qué orden se llaman los callbacks?

```xml
<a x="1">
  <b>t</b>
</a>
```

- [ ] `startDocument`, `startElement a`, `characters "1"`, `startElement b`, `characters "t"`, `endElement b`, `endElement a`, `endDocument`
  > Los atributos llegan en `startElement` (parámetro `Attributes`), no en `characters`.
- [x] `startDocument`, `startElement a`, `startElement b`, `characters "t"`, `endElement b`, `endElement a`, `endDocument`
  > Correcta: orden del documento, y el atributo va dentro de `startElement a`.
- [ ] `startDocument`, `startElement a`, `endElement a`, `startElement b`, `characters "t"`, `endElement b`, `endDocument`
  > `b` está dentro de `a`: `a` se cierra al final.
- [ ] `startElement a`, `startElement b`, `characters "t"`, `endElement b`, `endElement a`
  > Faltan `startDocument` y `endDocument`.
- [ ] `startDocument`, `startElement b`, `startElement a`, …
  > Se respeta el orden del documento.
- [ ] `startDocument`, `startElement a`, `startElement x`, …
  > Un atributo no genera `startElement`.

Repasar: **B07.2, B07.3**.
</Quiz>

<Quiz id="b3-05" title="Acumulador sustituido">
El texto de `<nombre>Luis</nombre>` llega en dos llamadas: `"Lu"` y `"is"`. ¿Qué imprime este manejador en `endElement`?

```java
private String texto = "";

@Override
public void characters(char[] ch, int start, int length) {
    texto = new String(ch, start, length);
}
@Override
public void endElement(String uri, String local, String qName) {
    if ("nombre".equals(qName)) System.out.println(texto);
}
```

- [ ] `Luis`
  > Cada llamada **sustituye** el valor anterior.
- [x] `is`
  > Correcta: hay que acumular con `StringBuilder.append(ch, start, length)`.
- [ ] `Lu`
  > La segunda llamada sobrescribe la primera.
- [ ] `isLu`
  > No se acumula.
- [ ] Una cadena vacía.
  > La última llamada deja `is`.
- [ ] Lanza `SAXException` por texto fragmentado.
  > La fragmentación es un comportamiento permitido.

Repasar: **B08.1, B15.2.3**.
</Quiz>

<Quiz id="b3-09" title="Atributo ausente en SAX">

Las opciones indican qué devuelve cada una de las dos llamadas.

- [x] `"393"` y `null`
  > Correcta (B07.2).
- [ ] `393` (entero) y `0`
  > Los valores son `String`.
- [ ] `null` y `null`, porque los atributos llegan en `characters`.
  > Llegan en el parámetro `Attributes`.
- [ ] `"393"` y lanza `SAXException`.
  > No es un error pedir un atributo ausente.
- [ ] `"rollno=393"` y `null`

<Quiz id="b3-10" title="Manejador que reinicia en cada etiqueta">

<Quiz id="b3-12" title="Analizar sin lógica propia">

- [x] Lo analiza sin errores, pero no extrae ni muestra nada.

- [ ] Imprime todo el XML por consola.
  > No tiene lógica de impresión.
- [ ] Devuelve un `Document` con el árbol.
  > `parse` de SAX devuelve `void`.
- [ ] Guarda los datos en una lista interna.
  > SAX no guarda datos por la aplicación.
- [ ] Lanza `SAXException` porque no hay callbacks sobrescritos.

<Quiz id="b3-14" title="InputSource y setEncoding">
El archivo `f` está en UTF-8 y contiene acentos. ¿Qué ocurre?

```java
Reader r = new InputStreamReader(new FileInputStream(f), "ISO-8859-1");
InputSource is = new InputSource(r);
is.setEncoding("UTF-8");
parser.parse(is, handler);
```

- [ ] `setEncoding` corrige la decodificación y los acentos se leen bien.
  > Con un `Reader`, los bytes ya se decodificaron como ISO-8859-1.
- [x] Los caracteres ya llegan decodificados por el `Reader`; `setEncoding` no los reinterpreta y los acentos pueden salir mal.
  > Correcta (B08.4).
- [ ] El parser lanza un error por incoherencia de codificaciones.
  > No compara ambas.
- [ ] `InputSource` no admite un `Reader`.
  > Sí lo admite.
- [ ] El parser vuelve a leer el archivo en bytes.
  > Trabaja con el `Reader` recibido.
- [ ] Da igual: SAX siempre usa UTF-8.
  > Con bytes, el parser interpreta la declaración; con un `Reader`, usa los caracteres que recibe.

Repasar: **B08.4**.
</Quiz>
