<Quiz id="t4mn-01" title="Arranque con JPA estándar">
Un proyecto nuevo no quiere depender de la API propia de Hibernate y se configura con `META-INF/persistence.xml`. ¿Con qué objetos trabaja?

- [ ] `SessionFactory` y `Session`.
  > Son el arranque de Hibernate nativo con `hibernate.cfg.xml`.
- [x] `EntityManagerFactory` y `EntityManager`.
  > Correcta: es el arranque JPA estándar con una unidad de persistencia, y puede usar Hibernate como proveedor.
- [ ] `DriverManager` y `Connection`.
  > Es JDBC, sin mapeo de entidades.
- [ ] Los dos archivos, que siempre deben ir duplicados.
  > No son dos archivos que haya que duplicar obligatoriamente.

Repasar: 4A §3.
</Quiz>

<Quiz id="t4mn-02" title="Cuándo cerrar la fábrica">
¿Cuándo hay que llamar a `shutdown()`?

```java
public final class HibernateUtils {
    private static final SessionFactory FACTORY =
            new Configuration().configure().buildSessionFactory();
    public static SessionFactory getSessionFactory() { return FACTORY; }
    public static void shutdown() { FACTORY.close(); }
}
```

- [ ] Después de cada operación CRUD.
  > La fábrica se reutiliza durante toda la aplicación.
- [ ] Antes de abrir cada sesión.
  > Sin fábrica no se pueden abrir sesiones.
- [x] Una sola vez, al terminar toda la aplicación.
  > Correcta: es lo que indica el comentario del temario.
- [ ] Nunca: la fábrica se cierra sola con cada `Session`.
  > Cerrar una sesión no cierra la fábrica.

Repasar: 4B §4 y §5.
</Quiz>

<Quiz id="t4mn-04" title="El lado inverso de un uno a uno">
`Profesor.direccion` es el propietario de la relación. ¿Qué anotación lleva el lado de `Direccion`?

```java
@Entity
public class Direccion {
    @Id @GeneratedValue public Integer id;
    // ?
    public Profesor profesor;
}
```

- [ ] `@OneToOne @JoinColumn(name = "profesor_id")`
  > Crearía una segunda FK; solo un lado es propietario.
- [ ] `@ManyToOne(mappedBy = "direccion")`
  > No es una relación muchos a uno y `@ManyToOne` no admite `mappedBy`.
- [ ] `@OneToOne(mappedBy = "profesor")`
  > `mappedBy` apunta al atributo del propietario, que es `direccion`.
- [x] `@OneToOne(mappedBy = "direccion")`
  > Correcta: el inverso nombra el atributo del propietario.

Repasar: 4A §4, uno a uno.
</Quiz>

<Quiz id="t4mn-05" title="Muchos a muchos con dos tablas intermedias">
Las dos entidades declaran su propio `@JoinTable` para la misma relación. ¿Qué problema tiene?

```java
// En Profesor
@ManyToMany @JoinTable(name = "profesor_modulo")
public Set<Modulo> modulos;
// En Modulo
@ManyToMany @JoinTable(name = "modulo_profesor")
public Set<Profesor> profesores;
```

- [x] Son dos relaciones independientes; un lado debe usar `mappedBy`.
  > Correcta: solo un lado declara `@JoinTable` y el otro usa `mappedBy = "modulos"`.
- [ ] Ninguno: las dos tablas se sincronizan solas.
  > Hibernate no sincroniza dos relaciones distintas.
- [ ] Falta `cascade = ALL` en los dos lados.
  > Con módulos compartidos `ALL` es peligroso, y no resuelve el problema.
- [ ] `Set` no se puede usar en muchos a muchos.
  > Sí se puede.

Repasar: 4A §4, muchos a muchos.
</Quiz>

<Quiz id="t4mn-06" title="Comprobar si existe">
Antes de dar de alta un usuario, el programa quiere saber si ya hay uno con ese `seq`. ¿Qué método encaja?

- [ ] `load`, porque es más rápido.
  > Puede devolver un proxy y retrasar la detección de una fila inexistente.
- [ ] `refresh`, para recargarlo.
  > Necesita una instancia gestionada que ya exista.
- [ ] `merge`, para crearlo si no existe.
  > Copia estado; no responde si existe.
- [x] `get`, que devuelve `null` si no existe.
  > Correcta: permite comprobar `null` en el momento.

Repasar: 4A §7.
</Quiz>

<Quiz id="t4mn-11" title="Declarar dos consultas nombradas">
¿Qué declaración es correcta?

```java
// A
@NamedQueries({
    @NamedQuery(name = "Profesores.findAll", query = "select p from Profesor p"),
    @NamedQuery(name = "Profesores.ByName",
                query = "select p from Profesor p where p.nombre = :nombre")
})
// B
@NamedQueries({
    @NamedQuery(name = "Profesores.findAll", query = "select p from Profesor p")
    @NamedQuery(name = "Profesores.ByName",
                query = "select p from Profesor p where p.nombre = :nombre")
})
```

- [ ] B, porque las anotaciones no llevan comas.
  > Dentro de un array de anotaciones los elementos se separan con comas.
- [x] A
  > Correcta: varias `@NamedQuery` en `@NamedQueries` van separadas por comas.
- [ ] Las dos.
  > B no compila.
- [ ] Ninguna: solo se permite una consulta nombrada por entidad.
  > `@NamedQueries` existe para declarar varias.

Repasar: 4C §5.
</Quiz>

<Quiz id="t4mn-13" title="Solo los nombres">
Un desplegable necesita únicamente los nombres de los profesores, sin cargar las entidades completas. ¿Qué consulta y tipo corresponden?

- [ ] `select p from Profesor p` → `List<Profesor>`, y después leer el nombre.
  > Funciona, pero carga entidades completas, justo lo que se quería evitar.

<Quiz id="t4mn-19" title="Cambios después de clear">
¿Qué nombre queda para el profesor 1, que era `Ana`?

```java
Transaction tx = s.beginTransaction();
Profesor p = s.get(Profesor.class, 1);
s.createQuery("update Profesor p set p.nombre = 'X' where p.id = -1").executeUpdate();
s.clear();
p.nombre = "Cambiado";
tx.commit();
```

- [ ] `Cambiado`, porque `p` se cargó en esta sesión.
  > `clear()` desconecta todas las entidades del contexto.
- [ ] `X`, por el UPDATE masivo.
  > El UPDATE no afecta a ninguna fila (`id = -1`).
- [x] `Ana`
  > Correcta: tras `clear`, `p` está separada y su cambio no se envía.
- [ ] Lanza excepción al modificar `p`.
  > Se puede modificar; simplemente no se sincroniza.

Repasar: 4C §6, contexto de persistencia.
</Quiz>
