**20 preguntas originales · 10 de 3A y 10 de 3B · cuatro opciones · una correcta.** Mezcla situaciones, afirmaciones I/II/III y fragmentos de código. El reparto 10/10 es de práctica, no una ponderación oficial.

Java 17 o posterior. Se omiten imports y el tratamiento de excepciones salvo que formen parte de la pregunta. En Java, `conexion` es una `Connection` abierta a MySQL con la base `emp`/`dept` original. En SQLite, las FK no están activadas salvo que el fragmento lo indique. **Cada enunciado repite los datos que necesita.**

<Quiz id="t3mn-01" title="Un pool de conexiones">
Una aplicación web atiende cientos de peticiones por minuto y abrir una conexión nueva en cada una es lento. El equipo quiere configurar las conexiones en un único sitio y reutilizarlas. ¿Qué recomienda el temario?

- [ ] Seguir con `DriverManager`, porque `DataSource` está obsoleto.
  > Es al revés: ninguno está obsoleto, y `DataSource` es el adecuado para pools.
- [x] `DataSource`, adecuado para configuración centralizada o un pool.
  > Correcta: `DriverManager` sigue siendo válido, pero no está pensado para reutilizar conexiones.
- [ ] `Class.forName` en cada petición para acelerar la conexión.
  > Cargar la clase no reutiliza conexiones.
- [ ] Un driver tipo 1 para no abrir conexiones de red.
  > El puente ODBC es histórico y no resuelve la reutilización.

Repasar: 3A §3, dependencias y registro.
</Quiz>

<Quiz id="t3mn-02" title="Saber con qué motor se trabaja">
Una herramienta de informes debe mostrar en su cabecera el nombre del gestor de base de datos al que está conectada. ¿Qué llamada lo obtiene?

- [ ] `rs.getMetaData().getColumnTypeName(1)`
  > Da el tipo de una columna de un resultado.
- [ ] `conexion.getCatalog()`
  > Devuelve el catálogo actual, como el nombre de la base en MySQL, no el producto.
- [x] `conexion.getMetaData().getDatabaseProductName()`
  > Correcta: `DatabaseMetaData` describe el motor y el driver.
- [ ] `DriverManager.getDriver()`
  > No existe sin argumentos y no da el nombre del gestor.

Repasar: 3A §6.
</Quiz>

<Quiz id="t3mn-03" title="Commit dentro del bucle">
`numeros` contiene los `empno` de 5 empleados que existen. Las dos primeras actualizaciones van bien y la tercera lanza `SQLException`, por ejemplo por un bloqueo. ¿Cuántas subidas quedan guardadas?

```java
conexion.setAutoCommit(false);
try (PreparedStatement ps = conexion.prepareStatement(
        "UPDATE emp SET sal = sal + 100 WHERE empno = ?")) {
    for (int numero : numeros) {
        ps.setInt(1, numero);
        ps.executeUpdate();
        conexion.commit();
    }
} catch (SQLException e) {
    conexion.rollback();
}
```

- [ ] 0, porque el `catch` hace `rollback()`.
  > `rollback()` solo deshace lo que no se ha confirmado.
- [ ] 5, porque la excepción no afecta a las anteriores.
  > La tercera falla y las dos últimas no se ejecutan.
- [ ] 3, porque la tercera se guarda antes de fallar.
  > La tercera falla antes de su `commit()`.
- [x] 2, las confirmadas antes del fallo.
  > Correcta: cada vuelta confirma la suya; para «todo o nada» el `commit()` va después del bucle.

Repasar: 3A §9.
</Quiz>

<Quiz id="t3mn-04" title="Afirmaciones sobre las propiedades ACID">
Lee las afirmaciones:

**I.** La consistencia exige que se respeten las restricciones y reglas al completar la transacción.

**II.** El aislamiento garantiza que ningún nivel permita anomalías entre transacciones.

**III.** La durabilidad hace que lo confirmado persista según las garantías del motor y su configuración.

¿Cuáles son correctas?

- [ ] Todas: I, II y III.
  > II es falsa: no todos los niveles evitan cualquier anomalía.
- [ ] Solo II y III.
  > II es falsa e I es cierta.
- [x] Solo I y III.
  > Correcta: el aislamiento regula cómo interactúan las transacciones, con niveles distintos.
- [ ] Solo III.
  > I también es cierta.

Repasar: 3A §9.
</Quiz>

<Quiz id="t3mn-05" title="Guardar un empleado sin jefe">
La columna `mgr` de `emp` admite NULL y guarda el `empno` del jefe. El nuevo empleado 8001 no tiene jefe. ¿Qué línea completa correctamente el parámetro 4?

```java
PreparedStatement ps = conexion.prepareStatement(
        "INSERT INTO emp (empno, ename, job, mgr, deptno) VALUES (?, ?, ?, ?, ?)");
ps.setInt(1, 8001);
ps.setString(2, "NURIA");
ps.setString(3, "CLERK");
// parámetro 4
ps.setInt(5, 10);
```

- [ ] `ps.setInt(4, 0);`
  > Guardaría el jefe 0, que no es lo mismo que no tener jefe.
- [ ] `ps.setString(4, "NULL");`
  > Guardaría el texto `NULL`, no un nulo SQL.
- [x] `ps.setNull(4, Types.INTEGER);`
  > Correcta: `setNull` con el tipo SQL de la columna.
- [ ] No asignarlo: JDBC pone NULL en los `?` vacíos.
  > Cada `?` necesita un valor; MySQL lanza error si falta.

Repasar: 3A §5.
</Quiz>

<Quiz id="t3mn-06" title="Columnas por posición con SELECT *">
`emp` tiene las columnas `empno, ename, job, mgr, hiredate, sal, comm, deptno`, en ese orden. El empleado 7839 es KING, con oficio PRESIDENT. ¿Qué imprime?

```java
ResultSet rs = conexion.createStatement()
        .executeQuery("SELECT * FROM emp WHERE empno = 7839");
rs.next();
System.out.println(rs.getString(2));
```

- [ ] `7839`
  > Es la columna 1.
- [x] `KING`
  > Correcta: la columna 2 es `ename`; las posiciones empiezan en 1.
- [ ] `PRESIDENT`
  > Es la columna 3.
- [ ] Lanza excepción: con `SELECT *` hay que leer por nombre.
  > Se puede leer por posición, aunque depende del orden de las columnas.

Repasar: 3A §5, recorrer los resultados.
</Quiz>

<Quiz id="t3mn-07" title="Llamar a una función">
La función MySQL `salario_anual(p_empno INT)` devuelve un DECIMAL con el salario anual del empleado; el 7839 existe. ¿Qué posición tiene el valor devuelto?

```java
CallableStatement cs = conexion.prepareCall("{? = call salario_anual(?)}");
cs.registerOutParameter(1, Types.DECIMAL);
cs.setInt(2, 7839);
cs.execute();
```

- [ ] La 2, porque el IN va primero.
  > El primer `?` es el retorno, el que va antes de `= call`.
- [ ] Ninguna: el resultado lo devuelve `execute()`.
  > `execute()` devuelve un booleano sobre el primer resultado.
- [ ] La 0, reservada al retorno.
  > Las posiciones empiezan en 1.
- [x] La 1, que se lee con `cs.getBigDecimal(1)`.
  > Correcta: en `{? = call f(?)}` la posición 1 recibe el retorno.

Repasar: 3A §8.
</Quiz>

<Quiz id="t3mn-08" title="Una sentencia fija sin datos de usuario">
Un programa de instalación crea siempre la misma tabla, sin datos del usuario. ¿Qué es cierto?

- [x] Basta un `Statement` con `executeUpdate`, que devolverá normalmente 0.
  > Correcta: no hay valores que enlazar.
- [ ] Hay que usar `PreparedStatement` con un `?` para el nombre de la tabla.
  > Los marcadores no sirven para nombres de tablas.
- [ ] Hay que usar `executeQuery`, porque CREATE devuelve la tabla creada.
  > CREATE no devuelve filas.
- [ ] En MySQL se puede deshacer con `rollback()` si algo falla después.
  > El DDL en MySQL puede hacer un commit implícito.

Repasar: 3A §5 y §7.
</Quiz>

<Quiz id="t3mn-10" title="Ventas de varios cafés">
`ventas` es un `Map<String, Integer>` con el nombre de cada café y lo vendido esta semana. `semana` es un `PreparedStatement` de `UPDATE cafes SET ventas_semana = ? WHERE nombre = ?`. El bucle va dentro de una transacción (autocommit desactivado) cuyo `catch` hace `rollback()`; `nombre` es la clave primaria de `cafes`. ¿Por qué el código lanza la excepción del `if`?

```java
for (Map.Entry<String, Integer> v : ventas.entrySet()) {
    semana.setInt(1, v.getValue());
    semana.setString(2, v.getKey());
    if (semana.executeUpdate() != 1) {
        throw new SQLException("No se encontró el café " + v.getKey());
    }
}
```

- [ ] Para detener el bucle cuando el café no existe y no ocurra nada.
  > También sirve para que la transacción haga `rollback` de las ventas ya actualizadas.
- [ ] Porque `executeUpdate` siempre devuelve 1.
  > Devuelve 0 si el nombre no existe.
- [x] Porque un UPDATE sin coincidencias no falla solo, y así el `rollback` deshace todas las ventas.
  > Correcta: así se comprueba que cada café existe y la transacción confirma todo o nada.
- [ ] Porque `setString` falla con nombres de café inexistentes.
  > `setString` solo asigna el valor; no consulta la tabla.

Repasar: 3A §7 y §9.
</Quiz>

<Quiz id="t3mn-12" title="Resultados legibles en la consola">
Las consultas en sqlite3 salen como `Ana|Lopez`, sin cabecera. ¿Qué órdenes muestran los nombres de columna y alinean la salida?

```bash

```

- [ ] `.echo on` y `.timer on`

- [ ] `SET HEADERS ON;`
  > No es SQL de SQLite ni una orden de la consola.

<Quiz id="t3mn-14" title="Borrar un grupo con proveedores">
Base SQLite nueva y vacía. ¿Qué ocurre con el DELETE?

```sql
PRAGMA foreign_keys = ON;
CREATE TABLE supplier_groups (group_id INTEGER PRIMARY KEY, group_name TEXT NOT NULL);
CREATE TABLE suppliers (
    supplier_id INTEGER PRIMARY KEY,
    group_id INTEGER NOT NULL
        REFERENCES supplier_groups (group_id) ON DELETE RESTRICT
);
INSERT INTO supplier_groups VALUES (1, 'Mayoristas');
INSERT INTO suppliers VALUES (10, 1);
DELETE FROM supplier_groups WHERE group_id = 1;
```

- [ ] Borra el grupo y su proveedor.
  > Eso haría CASCADE.
- [x] Falla: RESTRICT rechaza borrar un grupo con proveedores.
  > Correcta: primero habría que reasignar o borrar el proveedor.
- [ ] Borra el grupo y deja `group_id` a NULL.
  > Eso haría SET NULL, y la columna es NOT NULL.
- [ ] Borra el grupo sin comprobar nada.
  > Las FK están activadas en esta conexión.

Repasar: 3B §6, acciones referenciales.
</Quiz>

<Quiz id="t3mn-17" title="Tabla estricta">
Base SQLite 3.37 o posterior, nueva y vacía. ¿Qué ocurre con el INSERT?

```sql
CREATE TABLE medidas (id INTEGER PRIMARY KEY, valor INTEGER) STRICT;
INSERT INTO medidas (valor) VALUES ('abc');
```

- [ ] Se guarda `'abc'` como texto.
  > Eso pasaría en una tabla ordinaria; STRICT añade comprobaciones de tipo.
- [ ] Se guarda 0.
  > SQLite no convierte `'abc'` en 0.
- [ ] Se guarda NULL.
  > No sustituye el valor por NULL.
- [x] Falla: en una tabla STRICT el valor no es compatible con INTEGER.
  > Correcta: STRICT rechaza lo que no puede guardarse como el tipo declarado.

Repasar: 3B §4.
</Quiz>

<Quiz id="t3mn-18" title="Una base de pruebas en Java">
¿Qué ocurre con los datos al terminar el `try`?

```java
try (Connection c = DriverManager.getConnection("jdbc:sqlite::memory:");
     Statement st = c.createStatement()) {
    st.executeUpdate("CREATE TABLE t (n INTEGER)");
    st.executeUpdate("INSERT INTO t VALUES (1)");
}
```

- [x] Desaparecen: la base en memoria vive mientras dura la conexión.
  > Correcta: es útil para pruebas que empiezan siempre de cero.
- [ ] Se guardan en un archivo llamado `memory`.
  > `:memory:` no crea ningún archivo.
- [ ] Se guardan porque el autocommit está activado.
  > Se confirman, pero la base desaparece al cerrar la conexión.
- [ ] Falla: SQLite necesita una ruta de archivo.
  > `jdbc:sqlite::memory:` es una URL válida.

Repasar: 3B §8, acceso desde Java.
</Quiz>

<Quiz id="t3mn-20" title="Bloqueo al escribir">
Dos programas abren la misma base SQLite. Uno ya está dentro de una transacción de escritura y el otro ejecuta `BEGIN IMMEDIATE`. ¿Qué puede ocurrir?

- [ ] Los dos escriben a la vez gracias a IMMEDIATE.
  > SQLite serializa las escrituras.
- [x] El segundo puede fallar porque ya hay otro escritor.
  > Correcta: IMMEDIATE intenta adquirir la escritura al empezar y puede fallar con otro escritor activo.
- [ ] El primero se deshace automáticamente.
  > IMMEDIATE no cancela otras transacciones.
- [ ] Se convierte en una transacción de solo lectura.
  > IMMEDIATE no cambia el tipo de la transacción a solo lectura.

Repasar: 3B §7.
