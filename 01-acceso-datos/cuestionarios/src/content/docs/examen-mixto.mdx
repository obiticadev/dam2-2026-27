**20 preguntas originales · 10 de A y 10 de B · cuatro opciones · una correcta.** Mezcla de situaciones y código de dificultad normal. El reparto 10/10 es una decisión de práctica, no una ponderación anunciada por el profesor. Sin tiempo límite ni penalización oficial supuestos.

Java 17 o posterior; JAXB 2 externo. Se omiten imports, gestión de excepciones y cierre de recursos. Las variables mencionadas están inicializadas y no hay errores de permisos ni cambios externos. Cada pregunta tiene su propio estado inicial. XML sin espacios entre etiquetas salvo indicación expresa; las clases JAXB tienen mapeos válidos. Sin NIO.

<Quiz id="mn-01" title="El propósito del almacenamiento">
Un sistema mantiene datos en una lista mientras está abierto, pero los pierde al salir. ¿Qué mejora resuelve directamente ese problema?

- [ ] Reemplazar la lista por un array.
  > Cambia la estructura en memoria, pero tampoco conserva sus datos al finalizar.
- [ ] Declarar la lista en un campo estático.
  > static mantiene estado de clase durante el proceso, no entre ejecuciones.
- [ ] Implementar un método que ordene la lista.
  > Ordenar no proporciona persistencia.
- [x] Guardar y recuperar los datos en un fichero.
  > Correcta: una representación persistente permite restablecerlos en la siguiente ejecución.

Repasar: A §1.
</Quiz>

<Quiz id="mn-02" title="Elegir por las necesidades">
Un editor necesita mover nodos de un XML pequeño y consultarlos muchas veces. ¿Qué criterio justifica escoger DOM?

- [x] Mantiene un árbol que puede navegarse y modificarse.
  > Correcta: responde a las consultas repetidas y a los cambios de estructura solicitados.
- [ ] Ofrece callbacks al encontrar cada etiqueta de entrada.
  > Describe SAX, pero no proporciona el árbol editable que necesita el editor.
- [ ] Consume los eventos solo cuando el cliente los pide.
  > Describe StAX; por sí solo no conserva el documento como árbol modificable.
- [ ] Convierte nombres de fichero en rutas absolutas.
  > Es una operación sobre rutas, no una solución de edición XML.

Repasar: B §1.2.
</Quiz>

<Quiz id="mn-03" title="Longitud cero">
No se sabe si `f` existe. ¿Qué conclusión permite esta salida?

```java
System.out.println(f.length()); // imprime 0
```

- [ ] Demuestra que existe y está vacío.
  > Un destino inexistente también puede dar longitud cero.
- [x] No basta para decidir si existe.
  > Correcta: hay que consultar su existencia o tipo; cero por sí solo es ambiguo.
- [ ] Demuestra que contiene una línea vacía.
  > length mide bytes, no líneas, y no garantiza que el recurso exista.
- [ ] Demuestra que el objeto f es null.
  > Si f fuera null, la llamada lanzaría una excepción en vez de imprimir cero.

Repasar: A §2.4.
</Quiz>

<Quiz id="mn-04" title="El texto de una etiqueta">
`n` representa el elemento siguiente. ¿Qué expresión obtiene la cadena `"18"`?

```xml
<edad>18</edad>
```

- [ ] `n.getNodeName()`
  > Devuelve el nombre edad, no su contenido.
- [ ] `n.getNodeValue()`
  > Para un Element devuelve null.
- [x] `n.getTextContent()`
  > Correcta: devuelve el texto del elemento; convertirlo a entero sería otro paso.
- [ ] `n.getParentNode().getNodeName()`
  > Consulta el nombre del padre, no el valor contenido en edad.

Repasar: B §2.3.
</Quiz>

<Quiz id="mn-05" title="Contar lo que se ha escrito">
¿Cuántos bytes escribe esta llamada?

```java
byte[] datos = {3, 6, 9, 12, 15, 18};
out.write(datos, 2, 3);
```

- [ ] Dos bytes: `9, 12`.
  > El tercer argumento indica cantidad, no el índice de fin.
- [ ] Seis bytes: todo el array.
  > Eso ocurriría con write(datos) sin rango.
- [ ] Cuatro bytes: `9, 12, 15, 18`.
  > Se detiene después de tres bytes, no al final del array.
- [x] Tres bytes: `9, 12, 15`.
  > Correcta: toma tres posiciones a partir del índice 2.

Repasar: A §2.7.
</Quiz>

<Quiz id="mn-06" title="Bajo consumo de memoria">
Se debe sumar un campo de millones de elementos XML mediante un manejador push, sin editar el documento. ¿Qué solución se ajusta mejor?

- [x] SAX con un acumulador del total.
  > Correcta: procesa eventos y conserva únicamente el estado necesario para la suma.
- [ ] DOM con todos los nodos cargados.
  > Puede calcular la suma, pero no responde a la necesidad de streaming push y memoria reducida.
- [ ] JAXB con una lista de todos los objetos.
  > Materializar todo el conjunto no es lo requerido y no usa el manejador push solicitado.
- [ ] StAX con peticiones explícitas de avance.
  > Es streaming, pero usa pull en lugar del modelo push pedido.

Repasar: B §3.
</Quiz>

<Quiz id="mn-07" title="Dejar escribir al búfer">
El programa quiere volcar lo pendiente sin cerrar el escritor. ¿Qué línea completa el fragmento?

```java
bw.write("proceso terminado");
// completar: el programa seguirá usando bw
```

- [ ] `bw.close();`
  > También vuelca, pero impide continuar usando el escritor.
- [x] `bw.flush();`
  > Correcta: envía el contenido del búfer al destino sin cerrar el flujo.
- [ ] `bw.newLine();`
  > Añade un separador de línea; no es la orden de volcado.
- [ ] `bw.toString();`
  > No escribe el contenido pendiente del escritor en su destino.

Repasar: A §2.10.
</Quiz>

<Quiz id="mn-08" title="El siguiente evento a petición">
¿Qué diferencia relevante hay entre el avance de StAX y las notificaciones SAX?

- [ ] SAX permite retroceder y StAX solo avanzar.
  > Ambos modelos de lectura son secuenciales y no retroceden automáticamente.
- [ ] StAX crea un DOM y SAX crea objetos JAXB.
  > Ninguno construye esas representaciones por el mero hecho de usar su API.
- [x] StAX pide eventos; SAX los notifica al manejador.
  > Correcta: contrapone pull y push sin confundirlos con memoria o representación.
- [ ] SAX escribe XML y StAX solo permite leerlo.
  > Es al contrario respecto a escritura: StAX incluye escritores y SAX es de lectura.

Repasar: B §4.
</Quiz>

<Quiz id="mn-09" title="Lectura incompleta del búfer">
Se leen bloques sobre un array reutilizado. ¿Por qué debe usarse `n` al escribir?

```java
while ((n = in.read(buffer)) != -1) {
    out.write(buffer, 0, n);
}
```

- [ ] Porque n siempre coincide con el tamaño del array.
  > Puede ser menor; precisamente por eso no se escribe siempre el array completo.
- [ ] Porque n indica dónde empezar en el fichero destino.
  > El argumento n es una cantidad; no es una posición absoluta del fichero.
- [ ] Porque n convierte los datos binarios en caracteres.
  > No hay conversión de codificación en este patrón de copia de bytes.
- [x] Porque solo n posiciones contienen datos recién leídos.
  > Correcta: evita copiar posiciones sobrantes, especialmente en una lectura parcial.

Repasar: A §2.7.
</Quiz>

<Quiz id="mn-10" title="Qué lista devuelve DOM">
`raiz` corresponde a `catalogo`. ¿Cuántos elementos devuelve la búsqueda?

```xml
<catalogo>
  <libro/>
  <seccion><libro/><libro/></seccion>
</catalogo>
```

```java
raiz.getElementsByTagName("libro").getLength()
```

- [x] `3`
  > Correcta: la búsqueda incluye todos los descendientes llamados libro.
- [ ] `1`
  > Solo cuenta el hijo directo e ignora los dos descendientes de seccion.
- [ ] `2`
  > Omite el libro que cuelga directamente de catalogo.
- [ ] `4`
  > seccion no se llama libro y no se incluye.

Repasar: B §2.3.
</Quiz>

<Quiz id="mn-11" title="Reconstruir no es imprimir">
¿Qué razón justifica guardar una Persona con ObjectOutputStream en lugar de guardar solo su toString?

- [ ] Permite evitar todos los errores de entrada y salida.
  > La serialización también puede fallar y requiere tratar sus excepciones.
- [x] Permite reconstruir el estado serializable del objeto.
  > Correcta: una descripción textual no define esa reconstrucción automática.
- [ ] Produce siempre un archivo más pequeño que el texto.
  > No hay garantía general de tamaño menor; tampoco es el propósito planteado.
- [ ] Evita que la clase necesite estar disponible al leer.
  > La deserialización necesita resolver las clases de los objetos guardados.

Repasar: A §2.8.
</Quiz>

<Quiz id="mn-12" title="El nombre de la raíz JAXB">
¿Qué determina esta anotación?

```java
@XmlRootElement(name = "inventario")
public class Catalogo { /* modelo mapeado */ }
```

- [ ] El nombre obligatorio del fichero XML.
  > El fichero destino puede tener otro nombre; la anotación configura el contenido XML.
- [ ] El nombre de todos los elementos descendientes.
  > Los hijos tienen sus propios mapeos y nombres.
- [x] El nombre del elemento raíz del XML.
  > Correcta: la clase Catalogo se representa como raíz inventario al serializarla.
- [ ] El nombre del paquete Java generado.
  > No renombra ni mueve la clase dentro de los paquetes Java.

Repasar: B §5.1.
</Quiz>

<Quiz id="mn-13" title="Después de leer un campo">
El puntero de RandomAccessFile está en 16 y hay suficientes datos. ¿Qué imprime?

```java
raf.readInt();
System.out.println(raf.getFilePointer());
```

- [ ] `16`
  > Leer consume bytes y desplaza el puntero.
- [ ] `17`
  > Un int ocupa cuatro bytes, no uno.
- [ ] `4`
  > El puntero es una posición absoluta, no la cantidad de bytes de la última lectura.
- [x] `20`
  > Correcta: avanza cuatro bytes desde el desplazamiento inicial 16.

Repasar: A §2.12.
</Quiz>

<Quiz id="mn-14" title="Guardar un DOM nuevo">
El documento tiene raíz `grupo`. ¿Qué línea hace que el alumno creado aparezca al transformar el DOM?

```java
Element alumno = doc.createElement("alumno");
alumno.setAttribute("id", "8");
// completar antes de guardar doc
```

- [x] `doc.getDocumentElement().appendChild(alumno);`
  > Correcta: inserta el nuevo nodo como hijo de la raíz del documento.
- [ ] `alumno.getTextContent();`
  > Consultar el texto no conecta el elemento al árbol.
- [ ] `doc.getElementsByTagName("alumno");`
  > Buscar nodos no inserta el que acaba de crearse.
- [ ] `doc.createAttribute("id");`
  > Crea otro atributo desconectado; el alumno seguiría fuera del árbol.

Repasar: B §2.5.
</Quiz>

<Quiz id="mn-15" title="Un identificador dentro del registro">
Los registros contienen int + double, sin cabeceras ni relleno. Se quiere leer el int del registro de índice 4. ¿Qué posición debe usarse?

```java
raf.seek(/* posición */);
int id = raf.readInt();
```

- [ ] `16`
  > Multiplica por el tamaño del int, pero cada registro completo mide doce bytes.
- [x] `48`
  > Correcta: el int es el primer campo; el registro empieza en 4 × 12.
- [ ] `52`
  > Es la posición del double, después del int del registro de índice 4.
- [ ] `36`
  > Es el inicio del registro de índice 3, no el del índice 4.

Repasar: A §2.12.
</Quiz>

<Quiz id="mn-16" title="Transformación o binding">
Se necesita recuperar un XML directamente como instancias de clases mapeadas, no como Document. ¿Qué operación se ajusta?

- [ ] Transformer sobre un DOMSource.
  > Transforma una representación de entrada; no es la recuperación JAXB del modelo de objetos.
- [ ] DocumentBuilder.parse sobre el fichero.
  > Devuelve un Document DOM, precisamente la representación que no se solicita.
- [x] Unmarshaller.unmarshal sobre el fichero.
  > Correcta: reconstruye el contenido como objetos según el mapeo JAXB.
- [ ] XMLStreamReader.next sobre la entrada.
  > Avanza un evento; no crea automáticamente las instancias del dominio.

Repasar: B §5.3.
</Quiz>

<Quiz id="mn-17" title="Seleccionar ficheros ordinarios">
Solo deben aceptarse ficheros ordinarios cuyo nombre termina en `.csv`, excluyendo directorios. ¿Qué predicado completa el filtro?

```java
dir.list((padre, nombre) -> /* condición */);
```

- [ ] `nombre.endsWith(".csv")`
  > No excluye directorios cuyo nombre tenga esa terminación.
- [ ] `new File(padre, nombre).isFile()`
  > Excluye directorios, pero acepta ficheros de otras extensiones.
- [ ] `nombre.endsWith(".csv") || new File(padre, nombre).isFile()`
  > El OR permite cualquier fichero ordinario o cualquier entrada con esa terminación.
- [x] `nombre.endsWith(".csv") && new File(padre, nombre).isFile()`
  > Correcta: ambas condiciones deben cumplirse para aceptar la entrada.

Repasar: A §2.6.
</Quiz>

<Quiz id="mn-18" title="Cerrar un elemento de texto">
Un manejador SAX acumula correctamente un nombre sencillo sin elementos anidados. ¿En qué evento conviene procesar el valor completo?

- [x] En endElement del nombre.
  > Correcta: para entonces han llegado todos sus fragmentos de characters.
- [ ] En startElement del nombre.
  > En la apertura aún no ha llegado el contenido textual.
- [ ] En la primera llamada a characters.
  > El texto puede llegar fragmentado; la primera llamada no garantiza el valor completo.
- [ ] En startDocument del XML.
  > Al comenzar el documento todavía no se ha leído el nombre.

Repasar: B §3.2.
</Quiz>

<Quiz id="mn-19" title="Recursos ante una excepción">
¿Qué ventaja concreta aporta esta forma de abrir el flujo?

```java
try (FileInputStream in = new FileInputStream("datos.bin")) {
    procesar(in);
}
```

- [ ] Evita que procesar lance excepciones.
  > El procesamiento puede fallar; try-with-resources no elimina sus errores.
- [x] Cierra el flujo al salir, incluso si procesar falla.
  > Correcta: una vez abierto, se intenta cerrar el recurso al abandonar el bloque.
- [ ] Conserva abierto el flujo para el siguiente método.
  > La finalidad es la contraria: delimitar su uso y cerrarlo al salir.
- [ ] Convierte los bytes del archivo a Unicode.
  > FileInputStream sigue entregando bytes, sin decodificación de caracteres.

Repasar: A §2.9, try-with-resources.
</Quiz>

<Quiz id="mn-20" title="Formatear no es validar">
¿Qué hace esta configuración de JAXB?

```java
m.setProperty(Marshaller.JAXB_FORMATTED_OUTPUT, true);
```

- [ ] Valida los objetos con el esquema XSD.
  > El formato de salida no activa validación de esquema.
- [ ] Guarda inmediatamente el XML en disco.
  > Configurar una propiedad no sustituye la posterior llamada a marshal.
- [x] Solicita una salida XML con formato legible.
  > Correcta: configura la presentación de la salida, como la indentación.
- [ ] Ordena las propiedades alfabéticamente.
  > El orden de elementos no se decide con esta propiedad; puede configurarse con propOrder.

Repasar: B §5.3.
</Quiz>
