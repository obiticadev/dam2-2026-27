Bloques **B09–B11**. Los fragmentos omiten los `import` y el manejo de `XMLStreamException`. `r` es un `XMLStreamReader` recién creado con `XMLInputFactory.newInstance().createXMLStreamReader(...)` sobre el XML indicado (se muestra indentado para leerlo mejor, pero el fichero no tiene espacios ni saltos de línea entre etiquetas); `er` es un `XMLEventReader` creado de la misma forma.

<Quiz id="b4-01" title="Pull frente a push">
¿Cuál es la diferencia principal entre StAX y SAX?

- [ ] StAX construye un árbol y SAX no.
  > Ninguno de los dos construye un árbol completo.
- [x] En StAX la aplicación pide el siguiente evento (pull); en SAX el parser llama al manejador (push).
  > Correcta (B09).
- [ ] StAX permite volver atrás en el documento.
  > No retrocede; como mucho se guardan eventos propios.
- [ ] SAX es pull y StAX es push.
  > Es al revés.
- [ ] StAX solo puede escribir XML.
  > Lee y escribe.
- [ ] StAX necesita JAXB para funcionar.
  > Es parte de `java.xml`.

Repasar: **B09, B15.1**.
</Quiz>

<Quiz id="b4-02" title="Estado inicial">
Sin haber llamado a ningún otro método, ¿qué devuelve `r.getEventType()`?

- [ ] `START_ELEMENT` de la raíz.
  > Antes de la raíz está el inicio del documento.
- [x] `XMLStreamConstants.START_DOCUMENT`
  > Correcta (B10.1).
- [ ] -1, porque aún no se ha leído nada.
  > Siempre hay un evento actual.
- [ ] `END_DOCUMENT`
  > Ese es el último.
- [ ] Lanza `IllegalStateException`.

- [ ] `CHARACTERS`

Repasar: **B10.1**.
</Quiz>

<Quiz id="b4-03" title="Recorrido de inicios">
¿Qué imprime para este XML?

```xml
<a>
  <b/>
  <c>t</c>
</a>
```

```java
while (r.hasNext()) {
    if (r.next() == XMLStreamConstants.START_ELEMENT) {
        System.out.print(r.getLocalName() + " ");
    }
}
```

- [ ] `b c `
  > La raíz `a` también produce `START_ELEMENT`.
- [x] `a b c `
  > Correcta: un inicio por cada elemento, incluido el vacío.
- [ ] `a c `
  > `<b/>` también tiene inicio.
- [ ] `a b c t `
  > `t` es texto, no un elemento.
- [ ] `a b b c c a `
  > Solo se imprimen los inicios.
- [ ] Nada: el bucle no entra porque el estado inicial es `START_DOCUMENT`.
  > `hasNext()` es `true` y `next()` avanza a la raíz.

Repasar: **B10.1, B09.2**.
</Quiz>

<Quiz id="b4-04" title="hasNext no avanza">

- [ ] `false`, porque el cursor está en el tercer evento.

- [ ] `false`, porque el cursor está en la raíz.
  > No ha avanzado nada.
- [ ] Lanza `IllegalStateException`.
  > Consultar el tipo es válido en cualquier estado.
- [ ] No compila: `hasNext()` devuelve `int`.

- [ ] Depende de la longitud del documento.

Repasar: **B10.1**.
</Quiz>

<Quiz id="b4-05" title="Dónde queda el cursor">
XML, sin espacios entre etiquetas:

```xml
<libro>
  <t lang="en">Hola</t>
  <p>9</p>
</libro>
```

El cursor está en el `START_ELEMENT` de `t`. ¿Qué imprime?

```java
String texto = r.getElementText();
r.next();
System.out.println(texto + " " + r.getLocalName());
```

- [ ] `Hola t`
  > `getElementText()` deja el cursor en el cierre de `t`, y `next()` avanza otra vez.
- [x] `Hola p`
  > Correcta: tras el cierre de `t`, el siguiente evento es el inicio de `p`.
- [ ] `Hola libro`
  > Antes del cierre de `libro` está `p`.
- [ ] ` t` (texto vacío)
  > El método devuelve el texto completo.
- [ ] `Hola` y lanza `IllegalStateException` en `getLocalName()`.
  > En un `START_ELEMENT` el nombre está disponible.
- [ ] `Hola 9`
  > `getLocalName` devuelve nombres de elemento.

Repasar: **B10.2**.
</Quiz>

- [ ] `true false`

- [ ] `false false`

- [ ] Lanza `XMLStreamException`.
  > `t` solo contiene texto.
- [ ] No compila: `next()` devuelve `XMLEvent`.

<Quiz id="b4-09" title="Atributos según el estado">
XML: `<t lang="en">Hola</t>`. ¿Qué imprime?

r.next();   // START_ELEMENT de t
System.out.print(r.getAttributeValue(null, "lang") + " "
        + r.getAttributeValue(null, "color") + " ");
r.next();   // CHARACTERS
System.out.println(r.getAttributeValue(null, "lang"));

- [ ] `en  en` (vacío en medio)

- [ ] `en null en`

- [x] `en null ` y después lanza `IllegalStateException`.
  > Correcta: los atributos solo se consultan en `START_ELEMENT`.
- [ ] `null null null`
  > En el inicio de `t` el atributo existe.
- [ ] Lanza `IllegalArgumentException` por el `null` del primer parámetro.
  > `null` como URI significa no comprobar el espacio de nombres.
- [ ] `en  ` y después `null`.

<Quiz id="b4-11" title="next y nextEvent">
¿Qué línea **no compila**?

- [ ] `int tipo = r.next();`
  > Correcta en el cursor: devuelve `int`.
- [ ] `XMLEvent e = er.nextEvent();`
  > Correcta en la API de eventos.
- [x] `XMLEvent e = r.next();`
  > Esta no compila: en el cursor `next()` devuelve un `int`, no un `XMLEvent`.
- [ ] `boolean b = er.hasNext();`
  > `hasNext()` existe y devuelve `boolean`.
- [ ] `XMLEvent e = er.peek();`
  > `peek()` devuelve el próximo `XMLEvent` sin consumirlo.
- [ ] `int t = r.getEventType();`
  > Devuelve `int`.

Repasar: **B09.1, B11.2**.
</Quiz>

<Quiz id="b4-12" title="peek no consume">
XML: `<a/>`. Tras consumir con `er.nextEvent()` el `START_DOCUMENT`, ¿qué imprime?

```java
XMLEvent e1 = er.peek();
XMLEvent e2 = er.nextEvent();
System.out.println(e1.isStartElement() + " " + e2.isStartElement());
```

- [ ] `true false`
  > `peek()` no consume: `nextEvent()` devuelve el mismo evento.
- [x] `true true`
  > Correcta: los dos corresponden al inicio de `a`.
- [ ] `false true`
  > `peek()` ya muestra el inicio de `a`.
- [ ] `false false`
  > El siguiente evento es el inicio de `a`.
- [ ] Lanza `IllegalStateException` en `peek()`.
  > `peek()` es válido.
- [ ] No compila: `peek()` devuelve `int`.
  > En `XMLEventReader` devuelve `XMLEvent`.

Repasar: **B11.2**.
</Quiz>

<Quiz id="b4-15" title="Cerrar el lector">
¿Por qué no compila este código en JDK 17?

```java
try (XMLStreamReader r = XMLInputFactory.newInstance()
        .createXMLStreamReader(new FileInputStream("a.xml"))) {
    // …
}
```

- [ ] Porque `createXMLStreamReader` no admite un `InputStream`.
  > Sí lo admite.
- [x] Porque `XMLStreamReader` no implementa `AutoCloseable`, así que no puede ir en un `try-with-resources`.
  > Correcta: se cierra en un `finally`, y el flujo de origen sí en el `try-with-resources`.
- [ ] Porque `XMLStreamReader` no tiene método `close()`.
  > Lo tiene, pero no implementa `AutoCloseable`.
- [ ] Porque falta capturar `SAXException`.
  > StAX usa `XMLStreamException`.
- [ ] Porque `XMLInputFactory` no tiene `newInstance()`.
  > Sí lo tiene.
- [ ] Sí compila; solo avisa de un recurso sin cerrar.
  > Es un error de compilación.

Repasar: **B11.3**.
</Quiz>
